Overlang

A programming language designed for coding agents rather than people. Types, effects and contracts are written out in every signature, code lives in a content-addressed store instead of files, and the compiler answers in JSON. It compiles to C.

This is an experiment, built in two days by Claude agents, to test one hypothesis. It is not a product, and the first measurement went against the central idea. The numbers are below.

What it tests

Hypothesis: a language designed for agents lets a coding agent finish the same tasks with fewer tokens and fewer failed rounds than Python or Rust, even though the agent has never seen the language in training.

Two levers were expected to carry it. Locality: agents spend most of their tokens reading, so a store that hands the agent exactly the definitions it needs should cut that cost. First-pass correctness: mandatory signatures, effects, exhaustive matching and contracts move errors to compile time, where they are cheap. A negative result was declared a result in advance: it would mean the familiarity tax dominates for a language no model was trained on.

Five commands

Code is added to a store, not saved in files. The agent works on definitions by name:

  • ov add app.ov typechecks, hashes and stores every definition.
  • ov ctx route prints the minimal context to work on one definition: its source, the signatures it calls, the types they mention.
  • ov edit route replaces one definition; its callers are re-hashed and re-checked automatically.
  • ov test runs the test blocks, then fuzzes every function that has a contract.
  • ov run main builds a native binary from the store and runs it.

Design decisions

Signatures and effects are mandatory

Every top-level function states its parameter types, return type and effects (!io, !fs, !net). Nothing is inferred at the top level, and a pure function cannot call one with effects.

No null, no exceptions

Option and Result are ordinary sum types, ? propagates them, and every match must be exhaustive. The only panics are contract failures and traps such as overflow, reported as JSON.

A content-addressed store

Each definition is keyed by the SHA-256 of its canonical form, with names kept as metadata. Renaming never changes a hash; editing a definition propagates the new hash to its dependents.

JSON diagnostics

The compiler's reader is a model, so every error is one JSON object with a code, a span, expected and actual values, and ranked fixes, often as text ready to insert.

Contracts fuzzed by the compiler

requires and ensures clauses are checked at runtime, and ov test generates inputs per type, shrinks failures and reports them. It found an overflow in the spec's own example.

Compiles to C

Monomorphized generics, one C file per definition cached by hash, Boehm GC, and overflow-trapping Int. The compiler is one Rust binary, ov.

What the first evaluation found

Both benchmarks were run once per task on 2026-10-31 with Claude Sonnet 5.5 as the agent. Benchmark A is 100 HumanEval tasks in Python, Rust and Overlang; benchmark B is 25 maintenance changes to a 178-line HTTP todo app in Python and Overlang. The predictions were written down before the runs.

The locality prediction failed

The central hypothesis, that a content-addressed store with a minimal-context command cuts what an agent reads on a maintenance task, failed at this scale. Overlang agents read 2.1 times as much as Python agents, for two measured reasons.

  • The card tax. A language the model has never seen costs about 8k tokens of reference card per task before any work starts: 58% of Overlang's read tokens in benchmark B. Every fresh agent pays it again.
  • The agents did not use the locality tool. ov ctx was called once in 25 runs. The typical agent listed the store and viewed most definitions in a loop, reading the whole program, and paid 63% more for it than the Python agent paid to read main.py.

What held up

Sonnet solved 99 of 99 HumanEval tasks in a language it had never seen, from a 3.5k-token card, with zero failed test rounds and three turns each. First-pass correctness in a new language was not the problem. In benchmark B the store workflow (edit by name, dependents re-checked, build from the store) worked first time in 24 of 25 runs, and no agent hit a compiler bug.

What it does not show: whether ov ctx saves tokens, because the agents did not take it. The next test is a program ten times larger, or a workspace where the store is the only interface. HumanEval is at the ceiling for this model in all three languages. Details and caveats are in RESULTS.md.

Built by agents

Overlang was built on 2026-10-29 and 2026-10-30 by Claude agents: Opus and Sonnet implementing, Fable overseeing and writing the spec. The plan budgeted $12,300 in tokens. The build agents used 3.35M tokens in total (the ledger in the plan has them per agent, and does not count the overseer). The evaluation was 349 agent runs and 64.0M tokens, 84% of them cache reads, about $57 at Sonnet list rates.

What came out: the ov compiler in Rust, a C runtime with SQLite and HTTP shims, the content-addressed store, contract fuzzing with shrinking, JSON diagnostics with ranked fixes, the todo app, and an evaluation harness with 155 HumanEval tasks in three languages and 25 maintenance tasks.
